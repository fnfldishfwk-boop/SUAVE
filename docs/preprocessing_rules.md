# 이번 분석의 범위와 전처리 기준

## 분석 범위

- 원본: `data/raw/online_retail_II.xlsx`
- 대상 시트: `Year 2009-2010`만 사용합니다.
- `Year 2010-2011` 시트는 이번 분석에서 제외합니다.

## 고객번호 결측 처리

- 사용자 지정 분석 기준: `Customer ID`가 결측인 거래는 비회원 주문으로 분류합니다.
- 이는 이번 분석을 위한 정의이며, 원본 데이터로 실제 회원 가입 여부가 검증된 것은 아닙니다.
- 원본 `Customer ID`는 유지하고, 결측값에 임의의 고객번호를 채우지 않습니다.
- 전처리 데이터에 `customer_type` 열을 추가합니다. 고객번호가 결측이면 `비회원`, 있으면 `회원`으로 분류합니다.
- 비회원 거래도 매출·주문·상품·국가·기간별 분석에 포함합니다. 취소·반품 등 다른 필터는 별도 기준을 따릅니다.
- 주문 수는 데이터 행 수가 아닌 전표 번호(`Invoice`) 기준으로 계산합니다.
- 비회원 전체를 한 명의 고객으로 취급하지 않습니다. 비회원 고유 고객 수·재구매율·고객별 RFM은 고객번호로 산출할 수 없으므로 해당 계산에서 제외합니다.
- 같은 전표 내 고객번호 존재 여부가 섞여 있으면 불일치로 확인하며, 임의로 고객번호를 보완하지 않습니다.

## 적용 상태

원본 파일은 변경하지 않습니다. 아래 확정 기준으로 상품 순매출 데이터와 대조 집계표를 생성합니다.

## 추가 전처리 요청과 현재 적용

- 원본 8개 열이 모두 같은 완전 중복 6,865행을 제거했습니다.
- 상품 설명 앞뒤 공백을 제거하고 빈 문자열도 결측으로 처리했습니다.
- 같은 상품 코드에 유일한 설명이 있는 경우에만 설명을 보완했습니다. 2,172행을 채웠고 759행은 설명이 모호하거나 없어 남아 있습니다. 이 수치는 중복 제거 후, 비상품·0원 제거 전 기준입니다.
- 비상품 제외 코드: `ADJUST`, `ADJUST2`, `AMAZONFEE`, `B`, `BANK CHARGES`, `C2`, `C3`, `D`, `DOT`, `GIFT`, `M`(소문자 포함), `POST`, `S`, `TEST001`, `TEST002`, `gift_` 접두 코드. 중복 제거 후 2,960행입니다.
- `DCGS...`, `SP1002`, `PADS` 등 실제 상품 설명이 있는 코드는 코드 형태만으로 제외하지 않습니다.
- 0원 단가 및 수량 0인 행은 중간 후보에서 제외했습니다.
- 대량 주문은 삭제하지 않고 검토 샘플로 저장했습니다. 양수 수량·양수 가격의 비상품 제외 후보 기준 IQR 상한은 28.5개, 수량 99백분위는 120개입니다. 통계적 기준 초과가 오류 또는 실제 주문임을 증명하지 않습니다.
- 사용자 확정: 취소·조정을 원거래에서 차감한 뒤 최종 금액이 0 이하인 항목을 제외합니다.
- 비상품 조정 코드를 제외하면 해당 코드의 금액도 상품 순매출에서 빠집니다. 회사 전체 회계 순매출과는 범위가 다를 수 있습니다.

실행 코드: `src/profile_retail.py`, `src/prepare_retail_candidate.py`.
중간 후보 파일은 `data/interim/`에, 검토 표는 `reports/tables/`에 저장했습니다.

## 순매출 차감 방법

- 원거래 연결 번호가 없으므로 다음은 실제 전표 연결이 검증된 결과가 아닌 분석용 추정 규칙입니다.
- 고객번호가 있고 고객번호·상품 코드·단가·국가가 같으며 취소보다 앞선 거래에 한하여, 가장 최근 거래부터 취소 수량을 차감합니다. 동시각인 경우 원본 행 순서를 사용합니다.
- 차감된 행은 원래 수량·금액과 반환 수량을 보존하고 `net_quantity`, `net_amount`를 추가합니다. 분석에는 순수량과 순금액을 사용해야 합니다.
- 전부 취소되어 순수량·순금액이 0이 된 행은 최종 양수 거래 데이터에서 제외합니다.
- 비회원 취소, 대상 기간 이전 구매의 취소, 단가가 달라 연결되지 않는 취소 등은 임의 배분하지 않습니다.
- 연결되지 않은 금액은 `unmatched_adjustments.csv`에 검토용으로 보존하며, 전체 상품 순매출 집계에는 부호를 그대로 반영합니다. 최종 양수 거래 데이터만 합한 금액은 전체 상품 순매출과 다를 수 있습니다.
- `net_sales_summary.csv`의 `full_product_signed_net_amount`가 제외 코드·완전 중복·0원 처리 후 전체 상품 순매출입니다. `final_positive_net_amount + unmatched_signed_amount`와 반드시 일치하도록 검증합니다.
- 차감 금액은 원래 구매 일시에 귀속됩니다. 원본 부호 거래를 거래일별로 합한 회계 기간 매출과는 월별 배분이 다를 수 있습니다.
- 최종 데이터: `data/processed/retail_2009_2010_net_sales.csv`.
- 연결 감사표: `reports/tables/return_matching_audit.csv`.
- 재실행: 앞의 중간 데이터 생성 후 `src/finalize_retail.py` 실행.
