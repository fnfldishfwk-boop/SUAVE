# Year 2009-2010 데이터 전처리 보고서

작성일: 2026-10-29 · 처리 기준 버전: 1.0

## 1. 목적과 결과

고객번호 결측을 비회원으로 분류하고, 중복·비상품·0원 거래를 정리한 뒤 취소 수량을 이전 구매에서 차감했다. 대량 주문은 수량이 크다는 이유로 제거하거나 상한값으로 치환하지 않았다. 원본 Excel은 변경하지 않았다.

| 항목 | 결과 |
|---|---:|
| 입력 데이터 | 525,461행 × 8열 |
| 최종 양수 거래 데이터 | 499,391행 × 14열 |
| 최종 데이터의 전표 수 | 20,433개 |
| 회원 거래 행 | 396,529행 |
| 비회원 거래 행 | 102,862행 |
| 최종 상품 설명 결측 | 0행 |
| 최종 양수 거래의 순금액 합계 | 9,594,675.404 |
| 미연결 취소·조정 금액 | −37,452.620 |
| 전체 상품 순매출 | **9,557,222.784** |

금액은 원본 단가의 단위이며 이 보고서에서 통화를 확정하지 않는다. 금액을 행별로 반올림하지 않았으며 표의 소수 셋째 자리 표기는 표시 목적이다.

**전체 상품 순매출은 최종 양수 CSV 합계와 다르다.** 연결할 수 없는 취소를 임의의 거래에 배분하지 않았기 때문이다. 전체 상품 순매출을 보고할 때는 미연결 금액까지 반영한 집계값을 사용한다. 비상품으로 제외한 수수료·배송비·할인·수동 조정 등의 금액은 포함하지 않으므로 회사 전체 회계 순매출과도 범위가 다르다.

## 2. 입력 범위와 읽기 규칙

- 입력 파일: `data/raw/online_retail_II.xlsx`.
- 대상 시트: 이름이 정확히 `Year 2009-2010`인 시트만 읽는다. `Year 2010-2011`은 사용하지 않는다.
- Excel 1행은 헤더다. 원본 2행부터 525,462행까지 총 525,461개 데이터 행이다.
- 원본 열 순서: `Invoice`, `StockCode`, `Description`, `Quantity`, `InvoiceDate`, `Price`, `Customer ID`, `Country`.
- 실제 거래 일시 범위: 2009-12-01 07:45:00 ~ 2010-12-09 20:01:00. 이 범위 안에서 추가 날짜 필터를 적용하지 않는다.
- `pandas.read_excel`을 사용하고 `Invoice`, `StockCode`, `Customer ID`를 문자열로 읽는다. 나머지는 pandas/openpyxl의 자동 형식 해석을 사용한다.
- 결측 판정은 pandas 3.0.1의 `read_excel` 기본값(`keep_default_na=True`, `na_filter=True`)을 따른다. 고객번호에 별도의 임의 식별자를 채우지 않는다.
- 시각에 시간대 변환을 적용하지 않는다. 원본 행 순서와 인덱스를 유지한다.

## 3. 고정 처리 순서

아래 순서를 바꾸면 중복 판정·상품명 보완·취소 연결 결과가 달라질 수 있으므로 순서까지 처리 기준에 포함한다.

### 3.1 원본 8개 열 기준 완전 중복 제거

1. 추가 열을 만들거나 공백을 제거하기 **전**에 원본 8개 열 전체를 비교한다.
2. `df.drop_duplicates()`의 기본값 `keep='first'`를 적용한다. 모든 열이 같은 행 중 원본에서 처음 나온 행만 남긴다. 결측값 비교는 pandas 기본 동작을 따른다.
3. 원본 인덱스를 재설정하지 않는다. 공백 정리나 상품명 보완 후 중복 제거를 다시 실행하지 않는다.
4. 제거 건수: 6,865행. 잔여: 518,596행.

### 3.2 상품명과 상품 코드 공백 정리

- `Description`에 `.str.strip()`을 적용해 앞뒤 공백을 제거한다. 결과가 빈 문자열이면 결측으로 바꾼다.
- `StockCode`에도 `.str.strip()`을 적용한다.
- 상품명 내부의 연속 공백, 대소문자, 구두점은 변경하지 않는다. `Country`, `Invoice`, `Customer ID`에도 별도 공백·대소문자 표준화를 적용하지 않는다.

### 3.3 같은 상품 코드로 상품 설명 결측 보완

1. 중복 제거와 공백 정리 후 전체 시트에서 비결측 설명을 상품 코드별로 모은다. 이 단계는 비상품·0원 거래 제외 **전**이다.
2. 상품 코드 비교는 대소문자를 구분한다.
3. 해당 코드의 서로 다른 비결측 설명이 정확히 **1개**일 때만 그 설명으로 결측을 채운다.
4. 설명이 없거나 2개 이상이면 채우지 않는다. 최빈값·유사 상품명·외부 정보를 사용하지 않는다. 이미 존재하는 설명을 덮어쓰지 않는다.
5. 이 단계에서 설명 결측은 2,931행이며 2,172행을 보완했다. 잔여 759행은 후속 필터 전 수치다. 공백만 있던 설명도 결측으로 바꾸므로 원본의 빈 셀 수와 다를 수 있다.
6. 설명 결측 자체를 이유로 행을 삭제하는 필터는 없다. 후속 거래 필터를 모두 적용한 최종 데이터에는 설명 결측이 0행이다.

### 3.4 회원 구분과 원래 거래 금액

- `Customer ID`가 결측이면 `customer_type='비회원'`, 비결측이면 `'회원'`으로 설정한다. 이는 사용자가 정한 분석상 분류이며 실제 가입 여부 검증을 의미하지 않는다.
- 비회원 주문을 유지한다. 비회원 전체를 하나의 고객으로 묶거나 고유 고객 수·재구매율 계산에 넣지 않는다.
- `line_amount = Quantity × Price`로 계산한다. 이 단계에서 음수 수량을 삭제하지 않는다.

### 3.5 비상품 코드 제외

공백을 제거한 상품 코드를 대문자로 변환한 **판정용 값**으로 아래 조건을 적용한다. 출력의 상품 코드 자체는 대문자로 덮어쓰지 않는다.

다음 코드와 정확히 일치하거나 `GIFT_`로 시작하면 제외한다.

```text
ADJUST, ADJUST2, AMAZONFEE, B, BANK CHARGES,
C2, C3, D, DOT, GIFT, M, POST, S, TEST001, TEST002
접두 조건: GIFT_
```

- 소문자 `m`도 `M` 조건으로 제외한다.
- 배송·수수료·할인·수동 조정·테스트·상품권을 일반 상품 매출 범위에서 제외하는 명시적 코드 목록이다. 설명 문자열만으로 추가 제외하지 않는다.
- 숫자 5자리 형식이 아니라는 이유로 상품을 일괄 제거하지 않는다. `DCGS...`, `SP1002`, `PADS` 등 목록에 없는 코드는 유지한다. 이 중에도 후속 0원·취소 조건에 해당하는 행은 해당 조건으로 처리한다.
- 2,960행이 제외되며 이 행들의 부호 포함 금액 합계는 −51,447.220이다.
- 제외 코드별 내역은 `reports/tables/excluded_nonproduct_codes.csv`로 저장한다.
- 코드 목록은 버전 1.0에서 고정한다. 새 코드를 추가하려면 기준 버전과 결과를 함께 갱신한다.

### 3.6 0원 및 수량 0 거래 제외

- 비상품 제외 후 `Price != 0 AND Quantity != 0` 조건으로 남긴다.
- 추가 3,647행이 제외되어 취소 차감 전 후보는 511,989행이다.
- 이 단계에서는 음수 수량을 유지한다. 현재 후보의 음수 가격은 0행이다.

### 3.7 취소 수량을 이전 구매에서 차감

원본에는 취소가 어느 원거래를 취소했는지 확정할 수 있는 연결 열이 없다. 아래 규칙은 **분석용 추정 연결**이며 실제 원전표 관계를 보증하지 않는다.

1. 보존된 원본 인덱스에 2를 더해 `source_excel_row`를 만든다. 이는 헤더를 포함한 원본 Excel 행 번호다.
2. `InvoiceDate` 오름차순, 이어서 `source_excel_row` 오름차순으로 정렬한다. 같은 시각이면 Excel에서 먼저 나온 행을 먼저 처리한다.
3. `Quantity > 0`, `Price > 0`이고 전표 번호를 대문자로 바꿨을 때 `C`로 시작하지 않는 행을 구매로 취급한다.
4. 구매의 초기 순수량은 원래 수량이고 초기 반환 수량은 0이다. 고객번호가 있는 구매만 연결 후보에 등록한다. 비회원 양수 구매 자체는 최종 데이터에 유지한다.
5. `Quantity < 0 AND Price > 0`인 행을 차감 대상으로 처리한다. `C` 접두어 여부와 관계없이 이 조건을 적용한다.
6. **고객번호·상품 코드·단가·국가가 모두 정확히 같은** 이미 처리된 구매만 연결한다. 상품 코드와 국가는 대소문자를 구분하며, 단가는 허용 오차 없이 저장된 수치로 비교한다.
7. 연결 후보 중 **가장 최근에 처리한 구매부터** 차감한다. 같은 시각이면 원본 행 번호가 큰 구매가 우선이다. 단, 취소 행보다 먼저 처리된 구매만 해당한다.
8. 한 구매의 남은 순수량까지만 차감한다. 부족하면 그 이전 구매로 넘어간다. 부분 취소와 여러 구매에 걸친 차감을 허용하며 미래 구매에는 차감하지 않는다.
9. 차감할 때 구매의 `net_quantity`를 줄이고 `returned_quantity`를 같은 수량만큼 늘린다.
10. 고객번호가 없거나 후보 구매 수량이 부족하면 미연결 잔여를 남긴다. 이후 구매가 나타나도 재연결하지 않는다.
11. 전표가 C로 시작하지만 수량이 양수인 경우나 음수 가격 등 다른 부호 조합은 `negative_price_or_inconsistent_cancellation` 사유로 별도 대조 대상에 남기고 양수 거래 파일에 넣지 않는다. 현재 결과에는 이 사유가 없다.

연결된 취소 금액 합계는 209,971.840이다. 차감 연결은 `return_matching_audit.csv`에 구매 행 번호·취소 행 번호·연결 수량·금액으로 기록한다.

### 3.8 최종 양수 거래 선정

- `net_amount = net_quantity × Price`.
- `net_quantity > 0 AND net_amount > 0 AND Price > 0`인 행만 최종 CSV에 저장한다.
- 음수 행을 먼저 삭제하지 않고, 차감을 마친 뒤 이 조건을 적용한다. 완전 취소 구매와 취소 행 자체는 최종 양수 거래 파일에서 제외된다.
- 후보 511,989행 중 취소 행 9,559행과 순수량이 0이 된 구매 3,039행을 제외하여 최종 499,391행이 남았다. 부분 취소 후 유지된 구매는 4,381행이다.
- 출력 순서는 거래 일시, 원본 Excel 행 번호 순이다.

## 4. 미연결 취소와 순매출 정의

| 미연결 사유 | 행 수 | 잔여 부호 금액 |
|---|---:|---:|
| 고객번호 결측 (`customer_missing`) | 186 | −2,541.810 |
| 같은 조건의 이전 구매 부족 (`no_earlier_matching_purchase`) | 1,887 | −34,910.810 |
| 합계 | 2,073 | **−37,452.620** |

미연결 행에는 일부 수량만 연결된 취소도 포함될 수 있다. 따라서 이 표의 행 수는 원거래 전체가 전혀 연결되지 않은 취소 건수라는 의미가 아니다. 금액은 미연결 **잔여 수량**만 기준으로 한다.

```text
전체 상품 순매출
  = 비상품·중복·0원 제외 후 원래 부호 거래 금액의 합계
  = 최종 양수 거래 net_amount 합계 + 미연결 unmatched_amount 합계
  = 9,594,675.404 - 37,452.620
  = 9,557,222.784
```

`unmatched_adjustments.csv`는 이 차이를 설명하는 검토·대조 자료다. 일반 분석을 위한 취소 전용 매출 집단으로 해석하지 않는다. 원거래를 임의로 만들어 전체 금액을 양수 거래에 배분하지 않는다.

취소 차감액은 연결된 **구매 일시**에 귀속된다. 따라서 이 파일로 산출한 월별 순매출은 취소 발생일 기준의 회계 매출과 다를 수 있다. 전체 기간 순매출에는 미연결 금액도 포함해야 하며, 상품·회원·국가별 상세 순매출에서도 같은 범위의 미연결 금액을 대조해야 한다.

## 5. 대량 주문 유지 기준과 확인

대량 주문은 별도 삭제·수량 제한·금액 제한·윈저라이징을 하지 않는다. 일반 중복·비상품·0원·취소 조건만 동일하게 적용한다. 큰 수량만으로 오류나 실제 주문 여부를 확정하지 않는다.

이상 범위 검토의 모집단은 비상품·0원 제외 후, 취소 차감 **전**의 `Quantity > 0 AND Price > 0` 행이다.

- pandas `quantile` 기본 선형 보간(`interpolation='linear'`)을 사용한다.
- Q1=1, Q3=12, IQR=11, 상한=`Q3 + 1.5 × IQR`=28.5개.
- `Quantity > 28.5`를 검토 후보로 표시한다. 해당 27,068행은 삭제 대상 수가 아니다.
- 수량의 99백분위는 120개다. 이는 참고값이며 제거 조건으로 사용하지 않는다.
- 최종 데이터에는 **순수량 > 28.5인 26,550행**이 유지되어 있다. 취소 전 수량이 28.5를 넘는 최종 행은 26,642행이다.
- 검토 샘플은 취소 차감 전 후보를 `Quantity`, `line_amount` 내림차순으로 정렬한 상위 30행이다. 저장본은 `bulk_order_samples.csv`다. 표본 추출에 난수는 사용하지 않는다.

최종 데이터에서 확인한 대량 주문 예시:

| 전표 | 상품 코드 | 순수량 | 순금액 |
|---|---|---:|---:|
| 497946 | 37410 | 19,152 | 1,915.200 |
| 501534 | 21099 | 12,960 | 1,296.000 |
| 501534 | 21091 | 12,960 | 1,296.000 |

## 6. 처리 단계별 행 수

| 단계 | 잔여 행 | 직전 단계 대비 감소 |
|---|---:|---:|
| 원본 대상 시트 | 525,461 | — |
| 원본 8열 완전 중복 제거 | 518,596 | 6,865 |
| 비상품 코드 제외 | 515,636 | 2,960 |
| 단가 0·수량 0 제외 | 511,989 | 3,647 |
| 취소 차감 후 최종 양수 거래 | 499,391 | 12,598 |

최종 단계의 감소는 취소 행 9,559행과 순수량 0 구매 3,039행이다. 상품명 보완·회원 구분·대량 주문 검토는 행을 제거하지 않는다.

## 7. 최종 데이터 열 정의

| 열 | 의미와 사용 규칙 |
|---|---|
| Invoice | 구매 전표 번호. 문자열 식별자로 읽는다. |
| StockCode | 앞뒤 공백을 정리한 상품 코드. 문자열로 읽는다. |
| Description | 앞뒤 공백 정리 및 유일 설명 규칙으로 보완한 상품 설명. |
| original_quantity | 취소 차감 전 수량. 원래 Quantity를 이름 변경한 열. |
| InvoiceDate | 구매 일시. |
| Price | 원래 단가. |
| Customer ID | 고객 식별자. 결측은 그대로 보존하고 문자열로 읽는다. |
| Country | 원래 국가 값. |
| customer_type | 고객번호 존재 시 회원, 결측 시 비회원. |
| original_amount | 원래 수량 × 단가. 원래 line_amount를 이름 변경한 열. |
| source_excel_row | 원본 시트의 Excel 행 번호. |
| net_quantity | 원래 수량에서 연결 취소 수량을 차감한 순수량. 수량 분석의 기본값. |
| returned_quantity | 이 구매에서 차감한 취소 수량. |
| net_amount | 순수량 × 단가. 최종 거래 분석의 기본 금액. |

최종 CSV는 UTF-8 BOM(`utf-8-sig`), 쉼표 구분, 인덱스 미포함이다. CSV 자체는 데이터형을 보존하지 않으므로 다시 읽을 때 `Invoice`, `StockCode`, `Customer ID`의 문자열 형식을 명시한다.

## 8. 재실행 방법과 환경

프로젝트 루트에서 아래 세 파일을 **순서대로 모두** 실행한다. 중간 파일은 이번 원본에서 다시 생성하며 이전 실행의 중간 파일을 섞어 사용하지 않는다. 각 스크립트는 같은 이름의 생성 파일을 덮어쓴다.

```powershell
$retailPython = 'C:/Users/SuA/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe'
& $retailPython src/profile_retail.py
& $retailPython src/prepare_retail_candidate.py
& $retailPython src/finalize_retail.py
```

다른 환경에서는 동일 버전의 Python과 라이브러리를 사용하고 실행 파일 경로만 바꾼다. `data/interim`, `data/processed`, `reports/tables` 폴더가 있어야 한다.

| 구성 요소 | 사용 버전 |
|---|---|
| Python | 3.12.14, Windows 64비트 |
| pandas | 3.0.1 |
| numpy | 2.3.5 |
| openpyxl | 3.1.5 |

난수·현재 시각·외부 조회를 처리 조건으로 사용하지 않는다. 동일 원본, 코드, 라이브러리 버전, 정렬·형식·결측 처리 규칙을 유지하는 것이 재현의 조건이다. 다른 운영체제에서는 CSV 줄바꿈 때문에 파일 해시가 달라질 수 있으므로 행과 값의 일치도 함께 확인한다.

중간 파일명과 `preprocessing_pending_summary.json`의 `pending` 상태 문자열은 기준 확정 전 작성된 코드의 명칭이다. 재실행 시에도 이 이름으로 생성되지만, 최종 상태와 수치는 `net_sales_summary.json` 및 본 보고서를 따른다.

SHA-256은 아래와 같다. 동일 결과 재현 시 먼저 원본과 코드가 일치하는지 확인한다.

확인용 PowerShell 예시:

```powershell
Get-FileHash -LiteralPath 'data/processed/retail_2009_2010_net_sales.csv' -Algorithm SHA256
```

저장된 CSV를 다시 읽어 다음 사항을 확인했다.

- 최종 행 수 499,391, 열 수 14. 모든 행의 순수량·순금액이 양수다.
- 상품 설명 결측 0행이며 설명 앞뒤 공백이 없다.
- 순수량=`original_quantity - returned_quantity`, 순금액=`net_quantity × Price`다.
- 최종 순금액 합계와 미연결 금액 합계가 전체 상품 순매출과 일치한다. 집계 차이는 0이다.
- 대량 주문 예시가 최종 데이터에 유지되어 있다.

재현 시 부동소수점 비교는 절대 허용 오차 `0.00001`을 사용한다. 계산 중간이나 각 행의 금액을 소수 둘째 자리로 반올림하지 않는다.
